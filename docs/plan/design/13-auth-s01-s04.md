## Goal

Design first-launch and login: splash, 3-slide onboarding (value prop of the multi-vehicle booking), phone login and mock OTP (demo code `123456`), with tablet layouts that reflow rather than letterbox.

## Inputs

- `TsLogo` (splash mark), `TsTextField` (`+62` prefix), `TsButton`, `TsChip`/page dots, `TsSnackbar`, `TsDialog`.
- Onboarding copy from PRD 04: (1) "Servis banyak motor, sekali booking", (2) "Atur servis & keluhan tiap motor secara terpisah", (3) "Pantau status tiap unit secara real-time".
- P1 rule: default + empty + one loading/error per screen; dark = default on each breakpoint.

## Open questions (ask at kickoff)

1. **Onboarding illustrations** — 3 `Generate svg` illustrations (one per slide), style approved in step 01: slide 1 several motors + one ticket, slide 2 per-motor checklist cards, slide 3 status timeline. Approve the three prompts before generating.
2. **Splash.** Mark only, or mark + fading wordmark (PRD: optional after ~400ms)? Design both states as notes?
3. **OTP input.** 6 boxed cells with auto-advance; show the demo hint "Kode demo: 123456" on screen? (Reviewers need it — recommended yes, labelled as demo.)
4. **Terms/privacy microcopy** wording and links on S03.
5. **Tablet-L** onboarding: slide content left + illustration right; auth: form left (max 480) + brand illustration right — reuse one onboarding illustration or a dedicated auth hero?
