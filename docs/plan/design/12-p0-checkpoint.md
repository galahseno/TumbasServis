## Goal

Per-step reviews judge screens in isolation. This step judges the **mandatory flow as a whole** (Home → Booking Success): consistency, continuity of data, dark mode, hygiene. After this step the P0 design is submission-grade on its own and ready to be built in Flutter.

**Pencil-only.** Decided at the kickoff (2026-09-24): all Figma work (test import, HTML export, plugin check, early-conversion gate) moves to steps 20–21, which now run **after the Flutter app build**.

## Scope

### Flow-level review dimensions

| Dimension | Check |
|---|---|
| Continuity | Same demo data on every screen: motors, plates, workshop, slot, unit codes, prices; arithmetic identical from S11 → S16 → S18 |
| Consistency | Same title size/position, same primary-CTA position and label style, stepper matches on S10/S11/S13/S15/S16, same dialogs for exit/destructive, same spacing rhythm |
| Continuity of state | Selections visible downstream (S10 → S11 tabs → S16 recap → S18 units) |
| Copy | Bahasa voice, `Rp` format, date/time format, terminology (Estimasi, Bengkel, Unit) uniform |
| Dark mode | Sweep every P0 dark frame: no low-contrast leftovers, glass/blur legible, illustrations readable |
| Tablet | 800 and 1280 layouts follow PRD 06 for every P0 screen; no letterboxed phone layouts |
| Stress | 360×640 and text ×1.3 frames exist for S05, S11, S16, S18 and are clean |
| Hygiene | Node names follow the convention; zero raw hex; zero detached instances; unused components list; placeholder flags all cleared |
| Accessibility | Every icon-only control has a semantics note; every status/state has a non-color cue; every disabled control explains itself |
